# Новый персонаж: инструкция и чек-лист

Пошаговое руководство для того, кто добавляет в [`ui-agent`](character.md) новый вид тела —
человека или ИИ-агента. Оно полное: если идти по шагам и закрыть чек-лист в конце, персонаж
будет ходить, жестикулировать, носить предметы, играть общие сценки и свои.

Прежде чем начинать, прочитай две заметки целиком:

- [Визуальный стиль](visual-style.md) — **как персонаж должен выглядеть**: плоский цвет,
  простые фигуры, палитра, обводка только у белого, мозаика, тень, размеры. Всё, что ты
  рисуешь, проверяется по её чек-листу приёмки.
- [Персонаж рабочего стола](character.md) — архитектура, формат `agent.json` и `rig.json`,
  словарь имён привода, сценки и предметы.

Образцы — пять готовых видов в `assets/`: `pig` (четвероногое, самое простое), `raccoon`
(маска, полосатый хвост), `goose` (двуногое, шея дугой, крылья, клюв), `penguin` (тело
торчком, живот, ласты), `elephant` (хобот, уши, общая обводка). Бери ближайший и правь.

## Из чего состоит персонаж

| Что | Где | За что отвечает |
|---|---|---|
| Имя вида | `RigKind` в `src/rig/mod.rs` | перечисление, `name()`, `ALL` |
| Сложение | `Build` в `src/rig/creature/build.rs` | **как тело движется**: рост, шаг, шея, ноги |
| Манифест | `assets/<вид>/agent.json` | действия, длины клипов, скорость, нрав |
| Внешность | `assets/<вид>/rig.json` | **как тело выглядит**: кости, части, точки крепления |
| Вшивка | `Character::builtin` и `builtin_rig` в `src/assets/loader.rs` | набор в бинарнике |
| Свои сценки | `src/sim/stunt/<вид>.rs` и `src/sim/stunt/<вид>/` | шутки записки, истории вида |
| Тесты | `src/sim/tests.rs`, `src/sim/stunt_tests/<вид>.rs` | поведение и сценки |

Кода отрисовки под вид **нет**: всех рисует один рендер по `rig.json`. Если тебе кажется,
что нужна новая функция рисования, — это почти наверняка новая часть в файле вида.

## Единицы и оси

- **Design px** — логические пиксели при 100 %; на масштаб экрана умножает движок. Гусь целиком
  — около 35 px в высоту, свинка — около 30. Деталь мельче 1,3 px превращается в грязь.
- **Оси кости**: `x` — вперёд (куда смотрит нос), `y` — вправо, `z` — вверх.
- **Повороты в `rig.json`** — градусы `[по земле, подъём носа, вокруг оси вперёд]`.
- **Камера** смотрит на землю сверху под 30°. Шар на экране — круг. Высоты всего на рабочем
  столе идут один к одному, поэтому кости тела и ног помечаются `"ground": true` (их высоты
  растянуты так, чтобы 10 px высоты были 10 px на экране), а голова — нет: детали на ней
  ложатся проекцией шара.
- **Порядок частей в файле не влияет на картинку**: видно то, что ближе к зрителю.

## Шаг 1. Придумай вид на бумаге

1. Силуэт из 3–6 простых фигур: тело-эллипсоид, голова-шар, ноги-столбики. Он должен
   читаться с первого взгляда на сером и на белом фоне.
2. Палитра: 3–5 близких оттенков одной гаммы, самое тёмное — чернила `#1B1F29`. Чёрного нет.
   Цвета впиши в таблицу палитры `visual-style.md` и сверь, что вид не сливается с соседями.
3. Чем вид отличается в движении: ходит боком или нет, крадётся, ходит вразвалку, есть ли
   шея, хвост на пружине, уши, хобот. Это уйдёт в сложение.
4. Чем он несёт и трогает предметы — клюв, рыло, хобот, лапы. Это точка `muzzle`.

## Шаг 2. Имя вида

В `src/rig/mod.rs` добавь вариант в `RigKind`, в `ALL` (и поправь длину массива) и в
`name()`; допиши строку в тест `builtin_names_map_and_unknown_waves`.

## Шаг 3. Сложение (`Build`)

В `src/rig/creature/build.rs` заведи константу вида и ветку в `RigKind::build`. Все размеры —
design px, углы — радианы.

| Поле | Смысл | Как выбирать |
|---|---|---|
| `body_radii` | полуоси туловища: вперёд, вбок, вверх | от них считаются бёдра, тень, следы |
| `stand_z` | высота центра тела над землёй в стойке | низ тела = `stand_z − body_radii[2]` |
| `body_pitch` | наклон тела: 0 — горизонтально, 1,45 — торчком | у пингвина 1,45 |
| `neck_base` | основание шеи в осях тела: вперёд, вверх | точка на груди |
| `neck_rest` | голова от основания шеи в покое: вперёд, вверх | длина шеи |
| `curl_rest` | голова спящего в осях тела | куда ложится голова во сне |
| `neck_slack` | гибкость шеи, доля гусиной | 1 — длинная шея, 0,3 — шеи нет |
| `sidesteps` | может идти боком | только у гуся |
| `head_turn` | предел поворота головы от оси тела, рад | 0,8–1,4 |
| `head_radius`, `head_pitch` | радиус головы и её наклон в покое | |
| `muzzle` | клюв или рыло от поверхности головы | кончик = `0,7 × head_radius + muzzle` вперёд от центра головы |
| `print` | радиус отпечатка лапы | |
| `hind`, `fore` | пары ног: `along` — от точки под телом по ходу, `side` — разнос | `fore: None` у двуногого |
| `dangle_side`, `dangle_down` | где висят ноги, когда тело в руках | |
| `trunk`, `ears` | хобот и уши-лопухи | `None`, если их нет |
| `prowl` | на ходу тело ниже стойки на столько | у енота 3,5 |
| `stride` | доля обычного шага | у пингвина 0,55 |
| `waddle` | развалка, рад | у пингвина 0,28 |
| `gesture_wings` | бег и радость сами раскрывают крылья, уши или ласты | |

Проверь тестами `cargo test -p ui-agent rig::creature`: часть из них идёт по `RigKind::ALL`.

## Шаг 4. Манифест `assets/<вид>/agent.json`

Скопируй манифест свинки и поменяй `id`, `rig`, скорости и нрав:

```json
{
  "id": "fox",
  "rig": "fox",
  "scale": 1.0,
  "animations": { "idle": { "duration_ms": 1200, "loop": true }, "walk": { "duration_ms": 800, "loop": true } },
  "actions": { "idle": { "animation": "idle" }, "walk": { "animation": "walk" } },
  "motion": { "walk_speed": 70, "run_speed": 230 },
  "behavior": { "nap_weight": 0.3 }
}
```

- У набора с телом анимация — только `duration_ms` и `loop`. Полей `frame_size`, `anchor`,
  `frames`, `file`, `events` у него нет — их наличие даёт ошибку загрузки.
- Оставь все 17 действий образца (`spawn`, `idle`, `walk`, `run`, `look`, `react`, `interact`,
  `celebrate`, `think`, `busy`, `warning`, `error`, `sleep`, `wake_up`, `dragged`, `despawn`,
  `wave`): движок запускает их сам, тест требует не меньше 16.
- Нрав — веса `behavior` (`approach_cursor_weight`, `chase_cursor_weight`, `nap_weight`…).

## Шаг 5. Внешность `assets/<вид>/rig.json`

Формат и все поля описаны в [заметке о персонаже](character.md#вид-тела-скелет-из-rigjson).
Здесь — что обязано быть и как это собрать.

### Якорные кости

Привод ставит кости по позе тела **по именам**. Кости с этими именами обязаны висеть на
корне и стоять в покое без поворота (`turn` не задавать): поза задаёт их целиком.

| Кость | Обязательна | Родитель | Что с ней делает привод |
|---|---|---|---|
| `root` | да | — | точка на земле под телом; `"ground": true` |
| `body` | да | `root` | место, поворот, растяжение сценки, развалка; `"ground": true` |
| `head` | да | `root` | место и поворот головы; **без** `ground` |
| `foot_hind_l`, `foot_hind_r` | да | `root` | место ступни, поворот по ходу; `size` — выпущена ли лапа |
| `foot_fore_l`, `foot_fore_r` | у четвероногого | `root` | то же для передней пары |
| `neck_bend` | для шеи дугой | `root` | опорная точка дуги шеи |
| `neck_mid` | для узла на шее | `root` | середина шеи |
| `trunk_bend`, `trunk_tip` | для хобота | `root` | опорная точка дуги и кончик |
| `ear_l`, `ear_r` | для ушей-лопухов | `root` | шарнир, оси и длины лопасти |
| `tail_tip` | для хвоста на пружине | `body` | отставание кончика |

Кости, которых привод не знает (`hip_*`, `mouth`, `beak_*`, `wing_*`, `tail_bend`), — твои:
вешай их на `body` или `head` и двигай драйверами от регуляторов.

**Имя с опечаткой не даёт ошибки** — кость просто останется в покое. Если часть тела «не
идёт за телом», первым делом проверь имя.

В покое (`at`) ставь кости туда, где они стоят у спокойного персонажа: файл сам по себе —
поза покоя, привод считает сдвиг от неё.

### Точки крепления (сокеты)

| Сокет | Нужен | Где | Кто использует |
|---|---|---|---|
| `muzzle` | да | кончик клюва, рыла или хобота | симуляция: карточка, предмет в зубах, частицы, линия клювом |
| `head_top` | по соглашению | макушка | пока никто: точка для того, что наденут на голову |
| `back` | по соглашению | верх спины | пока никто: точка для того, что положат на спину |

Без `muzzle` вид загрузится — тест вшитых наборов его требует, а симуляция в запасе берёт
точку позы, — но предметы у морды разойдутся с картинкой. `head_top` и `back` есть у всех
пяти видов, чтобы будущие сценки могли на них опереться; ставь их тоже.

`muzzle` ставь на кости `head` в точке `[0,7 × head_radius + muzzle, 0, 0]` — там же, куда
решатель тянет голову (`Pose::muzzle_tip`), иначе предметы и курсор окажутся не у кончика.
У вида с хоботом сокет стоит на `trunk_tip` в нуле. Тест `muzzle_point_sits_on_the_drawn_muzzle`
проверит, что точка лежит на нарисованной морде.

### Регуляторы

Объяви в `controls` только те, что используешь. Привод заполняет их по именам:

| Регулятор | Значение | Для чего |
|---|---|---|
| `lids` | 0 или 1 | глаза закрыты: сон, моргание |
| `eyes_crossed`, `eyes_wide` | 0 или 1 | крестики (оглушён), распахнутые (испуг) |
| `mouth`, `mouth_open` | флаг и доля | рот открыт и насколько |
| `tongue` | 0 или 1 | язык набок |
| `beak_open`, `gape` | флаг и угол, рад | раскрытый клюв |
| `mud`, `snout_mud` | доля | грязь на теле и на морде |
| `has_wings`, `wings`, `flap` | флаг, доля, −1…1 | крылья, ласты: раскрытие и взмах |
| `has_knot`, `knot` | флаг и доля | узел на шее |
| `standing` | 0 или 1 | тело стоит: ногти, носки |

Часть показывается и прячется полями `show` и `hide`; кость двигается драйвером:

```json
{ "name": "wing_r", "parent": "body", "at": [-1.5, 8, 4.3], "stretch": [0, 0, 0],
  "drivers": [ { "control": "wings", "stretch": [1, 1, 1], "turn": [0, 0, 28.65] },
               { "control": "flap", "turn": [0, 0, 40.1] } ] }
```

### Рецепты частей

Числа бери из сложения: тело — `body_radii`, голова — `head_radius`.

- **Тело** — `ellipsoid` на `body` с полуосями `body_radii`.
- **Голова** — `ball` на `head` радиусом `head_radius`.
- **Шея** — `chain` на `body` от `neck_base` через `["head"]`; у длинной шеи — через
  `["neck_bend", "head"]` с `"curve": 9`.
- **Ноги** — кость бедра `hip_*` на `body` (в долях полуосей: около 0,55 вперёд, 0,5 вбок,
  0,5 вниз) и `chain` от неё через ступню с `"reach"`: нога не тянется за отставшей ступнёй,
  а поджатая уходит в тело. У двуногого лапка — `ball` или плоский `disc` на кости ступни.
- **Морда, уши, хвост** — `capsule` на `head` и `body`; хвост на пружине — `chain` через
  `["tail_bend", "tail_tip"]` с `curve`, кольца — `bands`, `"floor": true`.
- **Глаз** — блок из частей с одной привязкой `facing` на голове (доли радиуса головы:
  примерно 0,5 вбок, 0,6 вперёд, 0,4 вверх), всем — `"behind": true`:
  белок `ball` с `"rim"`, зрачок — `ball` со сдвигом к зрителю на радиус белка (всегда
  смотрит в камеру), веко (`show: ["lids"]`), крестик из двух `capsule`
  (`show: ["eyes_crossed"]`), распахнутый белок и зрачок (`show: ["eyes_wide"]`). Каждой
  части пропиши `hide` для остальных состояний — смотри блок глаз свинки.
- **Рот** — кость `mouth` на голове с `"stretch": [1, 0.3333, 1]` и драйвером от
  `mouth_open`; на ней `disc` с `facing` и `show: ["mouth"]`. Язык — `capsule` с
  `show: ["tongue"]`.
- **Клюв** — закрытый `capsule` (`hide: ["beak_open"]`) и две половинки на костях
  `beak_upper`/`beak_lower` с драйвером от `gape` (`show: ["beak_open"]`).
- **Грязь** — `disc` с `facing` на спине и `ball` на ступнях, `show: ["mud"]`; на морде —
  `show: ["snout_mud"]`.

### Когда часть не видна или видна не там

| Симптом | Причина | Что делать |
|---|---|---|
| рисунок на поверхности (живот, лицо, ноготь) не виден | он внутри тела, глубина честная | `"lift"`: на столько px ближе к зрителю |
| деталь просвечивает с затылка или торчит над головой | она на дальней стороне кости | `"behind": true`, глазам ещё `"sink": 0.7` |
| у белой части нет каймы на белом же теле | у них одна обводка — швов между своими нет | заведи вторую обводку в `outlines` и дай её части |
| кайма вокруг цветной части | по стилю обводка только у белого | убери `rim` |
| тело наклонено вдвое сильнее, чем надо | у кости из таблицы якорей задан `turn` в покое | убери: поворот задаёт поза |
| ноги или голова уехали от тела | имя кости с опечаткой или она не на корне | сверь с таблицей якорей |
| кольца хвоста сдвинуты | цвета `bands` считаются от кончика | первый цвет — цвет кончика |
| диск не виден | он смотрит изнанкой | поменяй местами оси в `axes` |
| зрачок или веко съехали | у `facing` координаты — вправо, **вверх**, к зрителю | проверь знак `y` |

## Шаг 6. Вшей набор

В `src/assets/loader.rs` добавь по ветке в `Character::builtin` (манифест) и
`Character::builtin_rig` (скелет). Тест `skeleton_comes_from_rig_json_next_to_the_manifest`
проверит кости `body`, `head`, ступни и сокет `muzzle`.

## Шаг 7. Подгонка глазами

Файл вида читается при запуске — пересобирать не нужно:

```bash
cargo run -p ui-agent --release --example preview_rig -- fox out.png idle,cycle --rig=assets/fox/rig.json
```

- Без фильтра рисуется всё: ходьба и бег по кадрам и 17 жестов в восьми направлениях.
- Накладки сценок: `antic:eyes=crossed;tongue=1;mouth=1`, `antic:roll=1.57`, `antic:lift=20;tuck=1`,
  `antic:wings=1;flap=0.2`, `antic:mud=1;snout=1`.
- Смотри каждую из восьми сторон: спереди, сзади, оба профиля, четыре вполоборота. Ошибки
  глубины видны именно сзади и вполоборота.
- Проверь на масштабах экрана 1, 1,5 и 3: тест `every_screen_scale_gives_the_same_body`
  ловит части, пропадающие на крупном.
- Сверься с чек-листом приёмки в [визуальном стиле](visual-style.md).

## Шаг 8. Предметы

Предметы рисует общий код (`src/render/props.rs`, модели — `src/effects/props.rs`); персонаж
с ними только взаимодействует. Чтобы новый вид сочетался с ними:

- **Размер.** Предмет соразмерен персонажу: мяч, яблоко, жёлудь — около головы или меньше.
  Сравни на кадрах сценки, а не по числам.
- **Точка захвата** — сокет `muzzle`. Предмет «в зубах» и карточка рисуются у неё, поэтому
  кончик морды должен быть на виду спереди и в профиль.
- **Дотянуться до земли.** Заведи в `src/sim/stunt/<вид>.rs` помощника по образцу
  `trunk_down` (`stunt/elephant.rs`), `paws_down` (`stunt/raccoon.rs`), `peck_pose`
  (`stunt/goose/crumbs.rs`) или `snout_down` (`stunt/pig/snack.rs`):
  накладка, при которой кончик морды касается земли на известном вылете перед телом
  (20–32 px). Вылет передаётся в `Sim::reach_for`, чтобы тело встало так, что морда попала
  на предмет.
- **Подарок.** В `src/sim/stunt/common/gift.rs` (`spawn_gift`) выбери, что вид приносит;
  без ветки он принесёт камешек.
- **Высота.** Предметы стоят на земле с высотой один к одному — как и «земные» кости. Если
  предмет у морды висит выше или ниже неё, неверно стоит сокет, а не предмет.
- **Новый предмет**, если он нужен виду, добавляется по разделу «Как добавить сценку»
  заметки о персонаже: вариант `PropKind`, рисование в `render/props.rs`, цвета — в палитру.

## Шаг 9. Сценки

Общие сценки (22 штуки) новый вид получает сам. Сверх того:

1. **Файл вида** `src/sim/stunt/<вид>.rs`: `NOTES` — пять-шесть шуток для записки — и
   помощник «дотянуться до земли». Подключи `mod <вид>;` в `src/sim/stunt/mod.rs` и добавь
   ветку в `Sim::notes`.
2. **Свои сценки** — по файлу на сценку в `src/sim/stunt/<вид>/`. Для каждой: константа
   вида и строка в таблице `stunts!` (`src/command.rs`), состояние с `begin_*`/`step_*`,
   строка в `acts!` (`src/sim/stunt/mod.rs`). Подробно — раздел «Как добавить сценку»
   заметки о персонаже. Хороший минимум — четыре сценки, как у слоника, енота и пингвина.
3. **Чем сценка управляет телом**: `Sim::antic` (накладка позы: `lift`, `squash`, `roll`,
   `pitch`, шея и голова, глаза, рот, язык, `wings`/`flap`, `knot`, `tuck`), `Sim::drive`
   (толчок тела), `Sim::cond` (последствия: грязь, оглушение), `Sim::props` (предметы).
   Всё, что сценка показывает на теле, должно быть в `rig.json` вида — иначе накладка есть,
   а на картинке ничего не меняется.
4. **Кадры глазами**:

```bash
cargo run -p ui-agent --release --example preview_stunt -- fox pounce out.png --ui 3 --crop 140,110
```
