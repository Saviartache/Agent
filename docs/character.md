# Персонаж рабочего стола (`ui-agent`)

Крейт `ui-agent` — движок анимированного
персонажа, который живёт на рабочем столе Windows (по духу — Desktop Goose):
ходит, отдыхает, реагирует на курсор и щелчки, приносит карточки уведомлений и
отражает состояние приложения (думает, занят, готово, ошибка). Приложение
(например, окно на iced) держит один дескриптор `Agent`, шлёт ему команды
и читает события; всё остальное происходит в отдельном потоке крейта.
Как всё это выглядит и как рисовать новое в том же духе — [Визуальный стиль](visual-style.md).

## Архитектурные решения

| Решение | Почему |
|---|---|
| Свои layered-окна и программная отрисовка (`UpdateLayeredWindow`), а не iced | Попиксельная альфа без прямоугольника фона и без фокуса; окна персонажа не зависят от цикла и рендерера интерфейса приложения и не блокируют его. Спрайты малы, CPU-смешивания хватает. |
| Несколько маленьких окон, а не одно на весь рабочий стол | Система сама делает попиксельный hit-test: щелчок по прозрачному пикселю проходит насквозь, окно персонажа и карточек не перехватывает чужие клики. Слой эффектов (следы, частицы) — `WS_EX_TRANSPARENT`, он не ловит мышь вовсе. Окно размером с экран стоило бы памяти и ловило бы мышь целиком. |
| Библиотечный поток, а не процесс-помощник | Нет IPC и второго бинарника, команда — запись в очередь, событие — чтение из очереди. Поток владеет всеми окнами, поэтому сообщения окон идут в его собственный цикл. |
| DPI-осведомлённость на поток (`SetThreadDpiAwarenessContext`) | Приложение-хозяин остаётся в своём режиме; поток персонажа получает физические пиксели и сам масштабирует мир по DPI монитора под персонажем. |
| Иерархический автомат + планировщик намерений, а не дерево поведения или utility AI | Жизнь (нет → появляется → жив → уходит) → режим (свободный, стоять, следовать, гнаться, спать) → намерение (бродить, отдыхать, смотреть на курсор…). Слоёв мало, порядок приоритетов виден в одном файле, ход воспроизводим по зерну. |
| Без смешивания клипов | Кадры набора рисует художник; смесь соседних клипов даёт кашу на пиксельной графике. Переход — смена клипа по приоритету. |
| Один поток без `Sleep` и опроса | Цикл ждёт `MsgWaitForMultipleObjectsEx` на таймер высокого разрешения, событие пробуждения и сообщения окон. Без анимации таймер выключен, поток спит с нулевой нагрузкой. |

## Карта модулей

```text
src/lib.rs          публичный API: Agent (Windows), Character, AgentConfig, Command, AgentEvent
src/command.rs      команды приложения; event.rs — события наружу; config.rs — настройки
src/companion.rs    Companion — спутник окна приложения: занятость → состояние, выходки, карточки
src/assets/         разбор набора (agent.json [+ PNG]) в Character; встроенные наборы — свинка и гусь
src/animation/      клип, проигрыватель (приоритеты, маркеры), твины
src/motion/         тело и рулёжка (приход, преследование, бегство, блуждание)
src/behavior/       мозг (FSM), планировщик намерений, предохранитель захвата курсора
src/effects/        следы, частицы, предметы сценок (листья, лужи), карточки (чистые модели)
src/rig/            процедурное тело: общий скелет creature (лапы, шея, жесты — чистая модель позы),
                    вид (RigKind: goose, pig) — сложение в creature/build.rs
src/render/         холст (premultiplied 0xAARRGGBB), scene — чистая отрисовка; creature — общее
                    для тел (холст, тень, проекция), goose и pig — сами виды;
                    shadow — общая тень точками, pixel — общая мозаика
src/sim/            Sim — детерминированная симуляция: мозг+движение+анимация+эффекты
src/sim/stunt/      сценки: mod.rs — запуск, шаг, выбор; common/ — общие, goose/ и pig/ — видовые
src/platform/       Win32: окна, поверхности DIB, текст GDI, курсор, мониторы, цикл ожидания
src/runtime/        поток персонажа: команды, события окон, кадр, отрисовка, таймер
src/agent.rs        дескриптор Agent (очереди и пробуждение)
examples/desktop_agent.rs   демонстрация;
examples/preview_rig.rs     контактный лист тела (pig | goose) в PNG для проверки глазами
console/            пакет scripts/build-package.sh: живая консоль-меню на ratatui, свой воркспейс
                    (её зависимости не попадают ни в библиотеку, ни к хозяину)
```

Граница чистоты: всё, кроме `platform`, `runtime` и `agent`, не вызывает ОС и не
читает часы — время приходит в `Sim::step(&Frame)`. Поэтому симуляция и отрисовка
проверяются на любой машине детерминированными сценариями.

### Единицы и масштаб

Мир — физические пиксели виртуального экрана (координаты бывают отрицательными).
`ui_scale = config.scale × dpi/96` умножает все «логические» расстояния и скорости
набора и настроек; `sprite_scale = ui_scale × scale набора` масштабирует спрайты.
DPI берётся у монитора под персонажем и перепроверяется раз в секунду.

## Как приложение пользуется `Agent`

```rust
use ui_agent::{Agent, AgentConfig, AgentEvent, Character, Notification, Status, rig::RigKind};

let character = Character::builtin(RigKind::Pig)?; // или RigKind::Goose
let agent = Agent::start(character, AgentConfig::default())?; // поток и окна готовы
agent.spawn()?;
agent.set_status(Status::Busy)?;
agent.notify(Notification::success("Выгрузка завершена").body("Реестр сохранён"))?;

while let Some(event) = agent.try_event() { // не блокирует
    match event {
        AgentEvent::ExitRequested => { /* пользователь выбрал «Выход»: решает приложение */ }
        AgentEvent::Clicked | AgentEvent::Dropped(_) | AgentEvent::Spawned => {}
        _ => {}
    }
}
agent.shutdown(); // закрывает окна и ждёт поток; то же делает Drop
```

Крейт — библиотека без своего окна и консоли: приложение подключает `ui-agent`
зависимостью, персонаж живёт в собственном потоке рядом с окном приложения.

Что можно сказать персонажу (все методы есть и у `Agent`, и у `AgentHandle`):

| Метод | Что делает |
|---|---|
| `set_status(Status)` | состояние приложения: `Thinking`/`Busy` держатся, `Success`/`Warning`/`Error` отыгрываются разово и сами возвращаются в `Normal` |
| `notify(Notification)` | карточка с сообщением: персонаж приносит её и кладёт рядом |
| `report(Status, Notification)` | состояние и карточка одним вызовом — итог операции |
| `play("имя")` | разовое действие набора; по окончании — `Played("имя")` |
| `hold("имя")` / `release()` | **своё состояние**: действие держится, пока не отпустят |
| `stage(Stunt)` | сценка (см. ниже); чужая для вида — молча пропускается |
| `surprise()` | что-нибудь случайное: разовое действие набора или сценка |
| `set_behavior(BehaviorMode)` | `Wander`, `Stay`, `FollowCursor`, `ChaseCursor`, `Sleep` |
| `move_to(Vec2)` | идти в точку экрана |
| `spawn()` / `spawn_at()` / `despawn()` | появиться / уйти (поток живёт дальше) |
| `pause(bool)` / `set_visible(bool)` | заморозить / спрятать |
| `send(Command)` | любая команда данными — для обёрток, которые получают команды извне |

- **Из нескольких мест программы:** `agent.handle()` даёт `AgentHandle` — копируемую
  ручку (`Clone + Send + Sync`) с теми же командами. Её можно раздать фоновым задачам
  и другим потокам; события остаются у владельца `Agent`. После остановки владельца
  все ручки отвечают `Err(Stopped)`.
- Каждый командный метод **не блокируется**: `Err(Busy)` — очередь (64) полна,
  команда отброшена; `Err(Stopped)` — поток остановлен.
- События (очередь 64) движок не ждёт: если приложение не читает, лишнее теряется.
- **iced:** держать `Agent` в состоянии приложения, опрашивать `try_event()` из
  подписки на таймер (`iced::time::every(100 мс)`) и в `update` реагировать на
  события; не звать ничего, что блокирует, из `update`/`view`. Единственная
  пауза UI-потока — короткое ожидание потока в `shutdown`/`Drop`.
- `Agent` — `Send`, но не `Sync` (приёмник событий): им владеет один поток.
- `ExitRequested`, `HiddenByUser`, `PauseToggled` приходят только от меню
  персонажа; `SetVisible(true)` возвращает спрятанного.

## Спутник окна приложения (`Companion`)

Окну приложения не нужен `Agent` напрямую: `ui_agent::Companion` — одна точка, поэтому
поведение у всех окон одинаковое, а окно не знает ни о потоке персонажа, ни о Windows
(вне Windows `Companion` — пустышка, крейт окна собирается и тестируется на любой машине).

```rust
let companion = Companion::start().unwrap_or_else(|_| Companion::disabled());
// на каждом тике окна:
companion.notify(card);                          // если операция дала итог
companion.set(activity);                         // идемпотентно
companion.tick();                                // выходки и события персонажа
```

| `Activity` | Что делает окно | Персонаж |
|---|---|---|
| `Connecting` | подключение | `Status::Thinking`, без выходок |
| `Working` | поиск, загрузка, выгрузка, сохранение… | `Status::Busy`; после 10–18 с работы — выходка (`surprise`: действие или сценка — круги, записка, лужа) каждые 18–40 с |
| `Idle` | готово, без ошибок | после работы — `Success`; гуляет, выходка каждые 35–90 с, свои сценки — как обычно |
| `Failed` | неудача или готово с ошибкой | `Error` разово, дальше как `Idle` |

Карточки — итог операции, которого ждут (выгрузка, скачивание…), или ошибка при переходе
работы в неудачу; то, что и так видно в окне, карточки не просит. «Выход» в меню персонажа
убирает только его — окно приложения живёт дальше.

## Набор персонажа (pack)

Персонаж бывает двух видов; поведение, анимационные часы, действия и приоритеты у них общие.

- **Процедурное тело** — `"rig": "goose"` или `"rig": "pig"` в `agent.json` (`Character::rig()`).
  Это встроенные наборы (`Character::builtin(RigKind)`, `assets/<вид>/agent.json`, PNG нет);
  `Companion` показывает **свинку**. Скелет у видов общий (`rig/creature`), вид
  задаёт сложение (`creature/build.rs`) и рисовальщик (`render/goose.rs`, `render/pig.rs`):
  - *гусь* — две лапы, длинная шея, голова на пружине; поднятая шея выгнута назад, опущенная —
    дугой вперёд от груди, без горба над спиной; голова, опускаясь вперёд, идёт дугой и не
    втягивает шею. Клюв к земле — `peck_pose` (кончик в 26 px перед телом), свинка опускает
    рыло вперёд за передние ноги — `snout_down` (пятачок в 22 px); сценка ставит тело так, чтобы
    кончик пришёлся на предмет (`Sim::reach_for`);
  - *свинка* — лупоглазая копилка: четыре ноги рысью (две пары по диагонали), шеи почти нет —
    голова сидит на теле, жесты шеи и отставание головы взяты в 0,3 от гусиных, поворот головы
    до 0,8 рад; два белых глаза навыкате со зрачком в камеру, закрытый глаз — светлое веко; спит, уронив
    голову перед собой. Карточку несёт у рыла. **Боком не ходит**: на ходу тело развёрнуто
    по скорости, а не по стороне, выбранной мозгом (гусь может идти боком — `sidesteps`
    в сложении); стоя разворачивается на месте. **Следы** — четыре дорожки: отпечаток копыта
    меньше гусиного (радиус 1,8 против 2,9), задняя пара стоит у́же передней, а новый след не
    ложится ближе диаметра к уже лежащему (`Footprints::stamp(.., clear)`) — иначе задняя нога,
    встающая в след передней, давала бы слипшиеся пятна. После лужи (`Stunt::MudBath`) свинка
    вымазана: бурые пятна на спине и комья на копытах (`Pose::mud`), а вместо серых следов —
    жирные бурые (живут 16 с вместо 4,5), бледнеющие шаг за шагом; грязи хватает на 90 шагов,
    стоя она обсыхает за 90 с. Новое появление — чистой.

  Тело рисуется из примитивов
  каждый кадр: лапы шагают и встают на землю (след — в точке приземления), шея и голова идут
  на пружине с запозданием, глаза моргают, взгляд поворачивается к цели. Процедурный, потому что
  живой скелет (шаг от скорости, шея от разгона, поворот на месте) не выразить конечным числом
  спрайтов и не развернуть во все стороны. Анимации набора несут только время: `file` запрещён,
  `frames` — сетка `{count, duration_ms}` (длина клипа), `loop`/`events` работают;
  `frame_size` и `anchor` обязательны схемой, но телом не используются. Действия отображаются
  на клипы как обычно, а тело читает имя показанного действия, долю клипа и по ним позирует:
  `idle/walk/run/look/react/interact/celebrate/think/busy/warning/error/sleep/wake_up/dragged/spawn/despawn`
  → одноимённый жест, любое другое имя (своё действие, например `wave`) — покачивание головой.
  Действия `turn` у тела нет: оно поворачивается непрерывно.
- **Спрайтовый набор** — папка с `agent.json` и PNG-листами (`Character::load_dir`); `file`
  обязателен. Набор грузится через `Character::load_dir`, готового набора в крейте нет
  (в демо: `--pack <папка>`).

Проверка вида: `cargo run -p ui-agent --example preview_rig -- <pig|goose> out.png [cycle,react,…]`
(кадры ходьбы/бега и жесты × четыре стороны на сером фоне, 2×).

| Поле `agent.json` | Смысл |
|---|---|
| `id` | имя набора |
| `frame_size` | `[w, h]` кадра по умолчанию, не нули |
| `anchor` | `[x, y]` точки опоры (ноги) в кадре; у анимации можно переопределить своим `anchor` |
| `scale` | множитель набора, `(0, 16]`, по умолчанию 1 |
| `animations` | имя → `file` (относительный путь с `/`, без `..`), `frames`, `loop`, `anchor`, `events` |
| `frames` | сетка `{count, duration_ms, columns?}` или список `{x, y, w, h, duration_ms, offset?}`; 1–256 кадров |
| `events` | `{frame, name}` — маркеры на границе кадра (например, `step`) |
| `actions` | имя → `{animation, priority, interruptible}`; приоритет выше не прерывается более низким, пока разовый клип не доигран |
| `motion` | `walk_speed`, `run_speed`, `acceleration`, `deceleration`, `arrive_radius`, `arrive_tolerance`, `edge_margin` (логические px) |
| `behavior` | веса и длительности намерений, радиусы замечания и контакта, порог «резкого» курсора |

Пределы: манифест ≤ 1 МиБ, PNG ≤ 16 МиБ и ≤ 4096×4096, суммарно ≤ 16 Мпикс,
≤ 256 анимаций, ≤ 4096 действий. Неизвестные поля — ошибка.

Встроенные имена действий, которые движок запускает сам: `spawn`, `idle`,
`walk`, `run`, `turn`, `look`, `react`, `interact`, `celebrate`, `think`,
`busy`, `warning`, `error`, `sleep`, `wake_up`, `dragged`, `despawn`.
Обязательны только `idle` и `walk`; отсутствующие заменяются ближайшими по смыслу
(`run`→`walk`, `celebrate`→`react`, `busy`→`think`…), а `turn`, `wake_up`,
`despawn` без замены пропускаются. Если разовое действие отображено на
зацикленный клип, мозг считает его доигранным после одного показа целиком.

**Своё действие:** добавить анимацию и действие в `agent.json` (например,
`"dance": { "animation": "dance", "priority": 1 }`) и вызвать
`agent.play("dance")`. По окончании придёт `AgentEvent::Played("dance")`.
Неизвестное имя молча игнорируется.

**Своё состояние:** то же действие, но удерживаемое — `agent.hold("dance")`; персонаж
стоит и играет его, пока не придёт `agent.release()`. Для состояния годится зацикленная
анимация (`"loop": true`). Список имён набора — `Character::action_names()`.

## Сценки и предметы

Сценка (`Stunt`) — маленькая история, которую персонаж разыгрывает сам. Сценки бывают
**общие** (у любого персонажа, и у спрайтового набора) и **видовые** (только у своего тела);
чья сценка — `Stunt::cast()`, список персонажа — `Stunt::roster(character.rig())`.

| `Stunt` | имя | Чья | Что происходит |
|---|---|---|---|
| `CursorHeist` | `cursor_heist` | общая | подбегает к курсору, хватает клювом/рылом и ≈5 с носится с ним зигзагами, потом бросает и радуется; только при `cursor_grab.enabled` (правила — ниже). Сам затевает и после погони за курсором |
| `Zoomies` | `zoomies` | общая | два круга бегом рядом с местом, где стоял; в конце звёздочки и встряска |
| `Note` | `note` | общая | приносит записку-шутку своего вида (тон «сведения», 5 с); только на пустой экран — карточки приложения не вытесняет; её закрытие тоже приходит `NotificationClosed` |
| `Chase` | `chase` | общая | гонится за курсором, не хватая; догнал — тормозит юзом и задирает голову; через 8 с сдаётся |
| `Boop` | `boop` | общая | тыкает курсор клювом/рылом (курсор не двигается); бывает, промахивается и катится кувырком |
| `Startle` | `startle` | общая | рефлекс: курсор резко пролетел рядом — подпрыгивает, глаза круглые, отскакивает (не чаще раза в 20 с); спящий не пугается |
| `Sneeze` | `sneeze` | общая | набирает воздух и чихает с отдачей; у грязной свинки вся грязь разлетается брызгами |
| `Hiccups` | `hiccups` | общая | восемь иков с подскоком и пузырём |
| `Dance` | `dance` | общая | переступает в ритм, нотки |
| `Stretch` | `stretch` | общая | потягивается, зевает, мотает головой |
| `Stare` | `stare` | общая | встаёт посреди экрана лицом к зрителю и следит головой за курсором; резко отворачивается |
| `Nap` | `nap` | общая | спит с «Z», иногда храпит; курсора не замечает; потом сонный |
| `Gift` | `gift` | общая | уходит за край, возвращается с пером/камешком/жёлудем и кладёт у курсора |
| `Ball` | `ball` | общая | пинает мяч трижды; мяч катится с вращением, отскакивает от краёв, курсор тоже его толкает |

**Озорные** сценки (`Stunt::naughty()`) играются только при `AgentConfig::naughty` (по
умолчанию выкл): на рабочем месте туалетный юмор неуместен. Демо их включает, `Companion` —
нет.

**Последствия.** Сценки оставляют на персонаже состояния (`sim/condition.rs`, всё 0…1, гаснет
само): грязная (стирается шагами), оглушён (шатается, звёздочки), раздута,
сонный (прикрытые глаза), грязный нос. На теле их показывает `Look`.

Запуск — `agent.stage(Stunt::…)`; доигранная сценка присылает `AgentEvent::StuntFinished(stunt)`,
сорванная — ничего. Чужая для вида или невозможная сейчас (нет курсора, захват выключен, на
экране карточки) молча пропускается. Сам персонаж затевает случайную сценку своего списка
раз в `behavior.stunt_gap_secs` секунд свободной прогулки (по умолчанию 150–400), если
`AgentConfig::stunts` включён; не вышла одна — пробует следующую. `surprise()` выбирает
между разовыми действиями набора и сценками. Сценку обрывает перетаскивание и `despawn`;
нетронутые куча и лужа исчезают сами. Сценка и `move_to` отвлекают и от
`Thinking`/`Busy`: поход в мозге выше работы, дойдя, персонаж возвращается к ней.

Предметы не кликабельны: они рисуются в окне эффектов под персонажем, мышь проходит сквозь.

**Где что лежит.** Код сценки — один файл в каталоге её владельца: `sim/stunt/common/`,
`sim/stunt/goose/`, `sim/stunt/pig/` (имя файла = имя сценки). Файл каталога (`common.rs`,
`goose.rs`, `pig.rs`) перечисляет его сценки и хранит то, что у вида своё (шутки записки
`NOTES`). `sim/stunt/mod.rs` — общий для всех: реестр `acts!`, запуск, шаг, выбор случайной,
помощники (`spot_away`, `halt`, `perform_quietly`); `sim/stunt/reflex.rs` — рефлексы
(испуг, отряхивание). Предметы — модели в `effects/`, сценарии — `sim/stunt_tests/`.

**Чем сценка управляет телом** (всё сбрасывается, когда сценка кончилась):

- `Directive::MoveTo/RunTo` — пойти или побежать; поход доводит тело до точки (6 px), а не
  до зоны касания. Вне походов сценки мозг держит персонажа на месте (`Senses::staged`):
  свободная прогулка во время сценки не включается, `halt()` значит «стой»;
- `Sim::antic` (`rig::Antic`) — накладка позы, задаётся заново каждый шаг: высота `lift`,
  сжатие `squash`, переворот `roll` (π/2 — на боку, π — на спине), поворот `spin`, шея и
  голова, глаза (`Eyes::Crossed`/`Wide`), рот, язык, крылья гуся `wings`/`flap`, узел шеи `knot`;
- `Sim::drive` (`Drive`) — толчок тела мимо мозга: юз, скольжение, отдача, полёт; упор в край
  экрана — `Sim::bumped`; с `overhang` тело заходит за край, и окно персонажа обрезается по
  монитору (`Sim::character_clip`);
- `Sim::cond` — состояния-последствия; `Sim::props` — предметы на земле (`effects/props.rs`:
  мяч, яблоко, жёлудь, кожура, кучка, яйцо, монета, ведро, крошка, камешек, перо, стрелочка,
  бабочка); `Sim::flock` — гусята; `Sim::scribble` — линия клювом; `Sim::trail` — путь курсора.

**Как добавить сценку** (всё в ядре, проверяется тестами без Windows):

1. Строка в таблице `stunts!` (`command.rs`): вариант, имя, чья, `naughty` при нужде.
2. Файл в каталоге владельца: состояние сценки и `impl Sim { begin_*() -> Option<_>;
   step_*(state, dt) -> Progress<_> }`. `begin_*` возвращает `None`, если сейчас нельзя;
   `step_*` — `Going(state)`, `Finished` (событие приложению) или `Dropped` (молча).
   Каждая сценка кончается за ограниченное время. Толкал тело или вёл — в конце `halt()`.
3. Строка в `acts!` (`sim/stunt/mod.rs`) и `mod` в файле каталога.
4. Новый предмет, если нужен, — файл в `src/effects/` по образцу `leaves.rs`/`mud.rs`:
   ограниченный пул, `update(dt)`, `iter()`, `bounds()`, `is_empty()`; поле в `sim::Sim`,
   шаг в `age_effects`, учёт в `is_dormant` и в `scene::Effects`; рисование — ветка в
   `scene::draw_effects`, охват — в `scene::effects_rect`. Тень предмета с высотой —
   `shadow::dotted(...)` до рисования самого предмета; плоское на земле (лужа) тени не
   имеет. Ретро-клетки на весь холст эффектов кладёт `pixel::retro`.
5. Сценарий в `src/sim/stunt_tests/` (общие файлы подключены к свинке, гусю и спрайту,
   видовые — к своему телу). Сценарии в режиме `Stay` прячут ошибки остановки: общий тест
   `every_stunt_finishes_while_wandering` гоняет все сценки в свободной прогулке, как на
   рабочем столе; превью тоже снимает в ней. Кадры глазами: `cargo run -p ui-agent --example preview_stunt
   -- <goose|pig> <сценка> out.png [--ui 3 --crop 140,110 --secs 8 --every 0.4]`.
6. Строка в таблице выше; снаружи сценку зовут по имени (`Stunt::from_name`).

## Настройки `AgentConfig`

| Поле | По умолчанию | Действие |
|---|---|---|
| `scale` | 1.0 | множитель размера поверх DPI и набора |
| `fps` | 60 | кадры в секунду, зажато в 10…120 |
| `seed` | системные часы | зерно поведения; одно зерно и одни входы — одна жизнь |
| `start` | низ первого монитора | точка появления |
| `footprints`, `particles` | вкл | следы и частицы |
| `draggable` | вкл | перетаскивание (сдвиг курсора > 6 px при нажатии) |
| `click_reaction` | вкл | реакция на щелчок; `Clicked` приходит всегда |
| `cursor_interest` | вкл | намерения «смотреть на курсор / идти к нему / гнаться» |
| `cursor_grab` | **выкл**, 5 с | кража курсора (`CursorHeist`), см. ниже |
| `context_menu` | вкл | правая кнопка: «Пауза/Продолжить», «Скрыть», «Выход» |
| `hide_in_fullscreen` | вкл | прятаться при полноэкранном приложении, презентации, блокировке |
| `stunts` | вкл | персонаж сам затевает сценки и рефлексы; по команде `stage` они играются всегда |
| `naughty` | **выкл** | озорные сценки (`fake_death`, `egg_surprise`, `oops`, `fart_jump`) |
| `max_items` | 3 | сколько карточек живёт одновременно (старейшая вытесняется) |

### Захват курсора — правила безопасности

Персонаж может украсть курсор, как в Desktop Goose: подбежать, схватить клювом или рылом
и носиться с ним (`Stunt::CursorHeist`). Выключено по умолчанию; включается
`cursor_grab.enabled = true` (в демо — флаг `--grab`). `Companion` его не
включает: мышью в окне водит пользователь. Держит курсор только
`CursorGrab` (`behavior/grab.rs`), обойти его нельзя: симуляция при выключенной настройке
не вызывает его вовсе, а сценка не начинается. Правила:

- держит `max_secs` (по умолчанию 5 с), но не дольше 6 с при любом значении; пауза между
  захватами ≥ 10 с (по умолчанию 120 с);
- любая нажатая кнопка мыши или Esc отпускает немедленно — персонаж вздрагивает, сценка
  считается сорванной;
- отпускает, если пользователь тянет курсор обратно (> 24 px от места, куда его поставили);
- курсор ведётся к клюву или рылу не быстрее 900 px/с — без прыжков;
- отпускает при потере курсора (экран блокировки), скрытии, полноэкранном приложении, паузе,
  перетаскивании, `despawn` и остановке;
- огромный шаг времени срок не продлевает.

## Полноэкранные приложения, блокировка, мониторы, DPI

- **Полноэкранное приложение, презентация, заставка/блокировка** (`SHQueryUserNotificationState`,
  проверка раз в секунду): окна прячутся, симуляция стоит, таймер — 1 с (только чтобы заметить
  возврат). Ничего не рисуется и курсор не трогается.
- **Скрыт командой или меню:** то же, но таймера нет вообще.
- **Несколько мониторов:** мир — виртуальный экран; персонаж ходит по рабочим областям
  всех мониторов. Карточка кладётся в монитор, где стоит персонаж.
- **Отключение монитора:** если персонаж дальше 200 px×`ui_scale` от любой области, его
  переносят на ближайший монитор сразу (через пустоту не идёт); карточки переносятся так же.
  Ближе — он сам возвращается шагом.
- **Смена DPI** (перенос окна, смена масштаба, переход на другой монитор): `ui_scale`
  пересчитывается, следы начинаются заново.
- Остановка внутри модального меню персонажа ждёт закрытия меню.

## Известные ограничения

- Только Windows 10+; под другими системами крейт собирает чистое ядро без `Agent`.
- Текст карточек — серое сглаживание GDI (Segoe UI), не ClearType; заголовок в одну строку,
  тело ограничено высотой карточки (92 логических px).
- Карточки не перестраиваются в стопке, когда нижняя закрылась.
- Нет звука и смешивания клипов; персонаж не знает об окнах других приложений
  (ходит поверх них по всей рабочей области, физики нет).
- Перетаскивание ограничено охватом всех мониторов; отпущенный в «пустоте» между
  мониторами персонаж возвращается шагом.
- `interruptible` из набора читается, но движок опирается только на `priority`.
- Окна `WS_EX_TOPMOST`: поверх них могут встать другие topmost-окна (при показе слоя
  движок повторно поднимает его).

## Демо и тесты

```text
cargo run -p ui-agent --example desktop_agent -- [--pack <папка>] [--rig goose|pig] [--grab]  # Windows
cargo test -p ui-agent                                                          # любая машина
cargo test -p ui-agent --target x86_64-pc-windows-gnu                           # на машине с Windows
cargo test -p ui-agent --offline --target x86_64-pc-windows-gnu --no-run        # только сборка
```

Демо: загружает набор, запускает `Agent`, персонаж появляется и живёт свободно, а
всё остальное управляется из консоли (`help` — справка): `play <действие>`,
`hold <действие>`/`release`, `stunts` — список сценок, `stunt <имя>`, `random`,
`status <состояние>`, `mode <режим>`, `notify <тон> <текст>`, `move <x> <y>`,
`spawn`/`despawn`, `actions` — имена действий набора. `all` прогоняет подряд все
действия, состояния, режимы и карточки; `demo` — короткий сценарий «думает → занят →
успех с карточкой»; `stop` прерывает прогон. `p` — пауза, `h` — скрыть/показать,
`q` — выход; «Выход» из меню персонажа тоже завершает демо. События печатаются.

Пакет (`scripts/build-package.sh`) собирает не демо, а `console/` — то же управление
выбором из меню: разделы слева (персонаж, действия, держать, сценки, состояние, режим,
карточки, прогоны, окно), пункты в середине, журнал событий справа, полоса прогона
снизу; клавиши и мышь. Смена тела и перехвата курсора перезапускает `Agent` с новым
`Character`, меню строится заново. «В фон» (`b`) перезапускает программу без консоли
(`--background`, `DETACHED_PROCESS`): управление — меню персонажа, «Выход» завершает
процесс, «Скрыть» возвращает консоль (`cmd /c start`, чтобы у неё были свои потоки
ввода-вывода). Меню, ввод и кадр проверяются тестами на любой машине
(`cargo test --manifest-path console/Cargo.toml`); сам агент и фон — только на Windows.

Что покрыто тестами на любой машине: сценарии `Sim` (появление, границы за 60 с,
огромный кадр, пауза, `Play`, статусы, карточки, щелчок/перетаскивание, потеря
монитора, DPI, следы, дремота, предохранитель захвата, детерминизм, сценки: каждая
доигрывается или честно отказывает и даёт свой главный эффект, чужие и озорные без
разрешения — отказ) и `render::scene`
(границы отрисовки, отражение, отрицательные координаты, карточки). Сценарии `Sim` идут
трижды — со свинкой, с гусём и с маленьким спрайтовым набором из памяти; `rig` (лапы не скользят и ходят по очереди,
число шагов от пути, а не от `dt`, покой, перетаскивание, конечность позы, охват холста,
детерминизм; у свинки — рысь на четырёх ногах и голова, не отрывающаяся от тела) и
`render::{creature, goose, pig}` тоже проверены без ОС.
Windows-тесты (`platform::*`, `agent::tests`: запуск → `Spawned` → остановка, `Drop`
без `shutdown`, команды после остановки → `Stopped`) требуют рабочего стола Windows.

## Ручная проверка на рабочем столе

- [ ] Прозрачность: вокруг персонажа нет прямоугольника, края гладкие.
- [ ] Нет кнопки на панели задач и в Alt+Tab.
- [ ] Набор текста в чужом приложении не теряет фокус при появлении, ходьбе, карточках.
- [ ] Щелчки проходят сквозь прозрачные пиксели персонажа, карточек, сквозь следы и частицы.

- [ ] Щелчок по карточке закрывает её (`NotificationClosed { by_user: true }`); по сроку — `by_user: false`.
- [ ] Правая кнопка: меню; закрывается щелчком мимо; «Пауза/Продолжить», «Скрыть», «Выход» работают, события приходят.
- [ ] Переход между мониторами с разным DPI: размер персонажа и шаги корректны, нет мерцания.
- [ ] Отключение монитора, на котором стоит персонаж или карточка: переносятся на оставшийся.
- [ ] Полноэкранное приложение (видео, игра) скрывает персонажа; по выходу он возвращается.
- [ ] Блокировка/разблокировка (Win+L): курсор не трогается, после разблокировки всё живо.
- [ ] Пауза, скрытие, выход; `--grab` и `stunt cursor_heist`: персонаж хватает курсор, ≈5 с
  носится с ним, курсор в клюве/у рыла не дёргается; нажатие кнопки/Esc отдаёт его сразу.
- [ ] Сценки `zoomies`, `note`, `leaf_pile` (гусь), `mud_bath` (свинка): лужа и грязный след
- [ ] `stunt peek`, `stuck`, `gift`, `edge_tumble`: персонаж обрезается по краю монитора и не

  (колонки «Объекты GDI», «Объекты USER») за 10 минут работы остаётся ровным (с карточками и без).
- [ ] Загрузка ЦП при простое (персонаж скрыт или не появился) ≈ 0; при ходьбе — единицы процентов.
